# Academy Writing · 学术写作规范

本项目团队自研技能的公开适配版，以计算机科学论文为主要应用场景。保留原版的三支柱：术语一致、表达精确、从真实文献学习领域写法。公开包不附带私人文献库或论文全文。

## 先判断任务

- **新写或重构论证**：按下述 Stage 0–4 推进。已有文献、术语与结果满足需求时复用，不重新收集一遍。
- **仅润色或翻译**：原文作为事实输入，直接进入 Stage 4。保持研究含义，不借润色新增结论或因果。
- **大型项目**：配合随包 paper-ops 管理底稿、实验来源及交付。
- **批注与审稿回复**：配合随包 seven-step-rebuttal 对应意见与修改。
- **英文文风精修**：可选配已安装的外部 ml-paper-humanizer；未安装时继续执行本技能，不声称使用了外部规则或脚本。

用户已指定的范围、材料权限和交付方式优先。不因语言任务运行实验、启动付费检索或更换正文数据。

## Stage 0–4

| 阶段 | 主要工作 | 产物 |
|---|---|---|
| 0 Anchor | 明确任务、读者、领域、语言、篇幅和已有证据 | 简要任务说明 |
| 1 Gather | 阅读相关原文并记录获取层级与用途 | 文献台账 |
| 2 Glossary | 确定概念规范名、定义及允许的语义差异 | 项目术语库 |
| 3 Learn-to-speak | 学习同领域论文怎样提出问题、比较和解释结果 | 带出处的句式与修辞笔记 |
| 4 Draft + Audit | 按论证写作，核对术语、事实、指代与可读性 | 正文与必要修改说明 |

Stage 0–3 的实施见 [references/learn-to-speak.md](references/learn-to-speak.md)。单段任务可以使用简短笔记，不强制新建整套文档。

## 三项写作原则

1. **一个概念一个规范名。** 已有作者术语优先，区分真正不同的概念与同义漂移，不为了换词而造新名。
2. **比较必须可定位。** 读者能从句子及邻近上下文确定比较谁、在哪个任务、用什么指标。无需每句重复全部设置。
3. **表达来自领域写法，结论来自自己的证据。** 可以学习段落功能和句法组织，不能借用其他论文的结果、独特措辞或缺少依据的定位。

## 起草与修订

先处理论证与段落顺序，再处理句法和词汇。段落应完成一个清楚的任务，如引入问题、定义机制、报告比较或解释现象。

- 事实陈述、理论结论、实验观察与研究预期使用相应表达；不要用谨慎套话代替具体条件，也不要把观察写成保证。
- 表格分析围绕研究问题选择有意义的比较，不逐格复述，也不掩盖改变结论的失败、负结果或适用范围。
- 仅有摘要或检索结果时，不写成已精读全文；新引用先核实再加入。
- 保护数值、单位、模型与数据集名称、数学表达、引用键和交叉引用，除非用户明确要求修改相应内容。
- 最小修改优先。作者原句准确自然时保留，不为展示工作量重写。

## 自审六项

1. **术语**：同一对象是否被换名，新术语是否有定义？
2. **指代**：比较与因果的主体是否明确？
3. **证据**：每个新结论是否在证据支持范围内？
4. **数字**：数值、分母、单位、版本是否与指定来源一致？
5. **表达**：是否有空泛判断、重复宣告、层叠保留语或无作用的连接词？
6. **保护项**：是否无意改变公式、标签、引用或作者已确认的措辞？

这是针对具体文本的检查，不是评分器。发现问题后定向修改，不凑固定轮数、不追逐未经校准的分数。

术语管理见 [references/glossary-bank.md](references/glossary-bank.md)；比较、数字及主张写法见 [references/precision-rules.md](references/precision-rules.md)。

## 输出

按用户要求给正文、修订稿或意见。需要解释时列出影响论证的主要改动及未解决的事实问题；用户只要一句话时只给一句话。不要把自审过程、内部标签或文件管理记录塞入论文正文。
