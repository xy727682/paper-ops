# 第 1 层：文件与版本管理

核心：**"改的是哪份、基于哪个版本"必须显式，禁止推断。**


## R1.1 底稿锁定

每轮开工第一件事：写下本轮底稿 = 路径 + 修改时间 + 文件哈希（`certutil -hashfile <f> SHA256` 或 python），记入工作日志。
- 换底稿必须用户明示
- "最新版"只能靠显式确认，不靠 mtime / v 号 / "看起来最全"

## R1.2 版本身份卡

关键产物（main.pdf、核心 tex、主结果表）各挂一张身份卡，记入工作日志或 MANIFEST.md：

```
文件: main.pdf
由: main.tex @ <源码版本>
数据快照: <当前数据版本>
状态: current | stale | archived
```

照 PDF 改源码前先核对身份卡：PDF 由哪版源码生成？不一致 → 以源码为准并标 PDF stale。

## R1.3 快照纪律

- 任何覆盖/大改前：tar.gz + SHA256 清单，进 `snapshots/`
- 产物一律进新目录；永不覆盖输入文件
- 交接他人：目录根放 README（状态、冻结声明、下一步、联系人），交接后停止修改该快照

## R1.4 任务注册表

多会话/多 agent 并行时维护 SESSION_REGISTRY.md：`会话ID → 任务 → 工作目录 → 状态`。向某会话/目录发指令前查表，禁止按文件时间猜归属。

## R1.5 历史材料标注

恢复旧内容（旧表、旧图、旧段落）必须带身份标："历史协议，未经当前核验"。带标内容不支撑任何结论；经核验（对得上 run 记录/台账）才摘标。

## R1.6 交付打包

- zip 一律正斜杠相对路径；打完后重新解包验证一次（编译或数标记，如 `\diffstart` 计数）
- 标记版/干净版分开命名：`*_marked.zip` / `*_clean.zip`，不混发
- 覆盖前查目标锁：WPS/Acrobat/在线编辑器占用则换文件名并提示用户关闭
- 上传失败先查 zip 内路径（反斜杠、绝对路径、中文名）

## 完成判据

- 工作日志里有本轮底稿三要素（路径/时间/哈希）
- 每个关键产物有身份卡且状态字段非 stale
- 本次所有覆盖操作都有对应快照
- 交付 zip 通过解包自检
