# Seven-Step Rebuttal · 七步改稿工作法

本项目团队自研的论文修订流程。AI 负责意见整理、草稿修改与对应核对，作者负责研究判断和最终表述。本文件是公开发行适配版，保留七步流程，不包含实际论文回复、私人批注或历史会话。

## 入口与范围

先从已有上下文确定底稿、修改范围和交付对象。信息已经明确时直接执行，不重复询问。复杂论文项目可配合随包的 `paper-ops` 管理版本、数据和交付；本技能也可独立使用。

- **精修**：只改指定句子及必要的关联引用，不顺带重写相邻段落。
- **粗修**：允许重排论证和段落，保护事实、术语、数值、公式及作者已确认的修改。
- **局部修改**：用一张 addressing 表即可，不强制产生全部流程文档。
- **完整审稿轮次**：按七步组织，允许按已完成的阶段接续。

语言润色可配合随包的 `academy-writing`，也可选用已安装的外部 `ml-paper-humanizer`。后者不随包提供，缺少时不阻断意见整理与修订，不自动下载，不声称已使用。

## 核心产物

| 产物 | 用途 |
|---|---|
| logic | 困难问题的立场、推理链、证据与缺口 |
| sheet | 每条意见的原文、回应、证据、正文落点和状态 |
| report | 本轮重要修改与未解决事项的简要汇总 |
| working draft | 供作者修改的工作稿，可按要求使用中英对照 |
| marked version | 显示修改位置和内容的版本 |
| clean version | 面向指定读者清理内部备注后的版本 |

简单轮次把 logic、sheet、report 合并成一份 addressing 文档。模板见 [templates.md](templates.md)。

## 七步流程

### ① 提取并定位批注

将 Word/PDF 批注对应到正文位置，保留批注者原话。必要时把一条意见拆成多个要求，但保留其共同来源。

- PDF 可用已有 PDF 工具提取批注内容、作者、页码和坐标，再对照页面定位。
- Word 可读 `word/comments.xml` 与 `word/document.xml` 的锚点；不因替换文本丢失修订或样式。
- 抽取错误可修正并记录；无法确定锚点时标记待定位，不自行编造原文。
- 意见可以进入工作稿内联标记，也可以留在独立表中，遵循用户选择。

### ② 组织回答与证据

困难问题先写 logic，其他问题直接填 sheet。每条回答交代立场、理由、证据与具体修改。

回复可认同、部分认同或有据反驳，不机械致谢后全盘接受。缺少实验或文献时明确所需材料；写作任务不自动授权补跑实验。

### ③ 从指定底稿生成工作稿

保留输入，建立独立工作副本。用户已指定可编辑副本时沿用它，不重复制造版本。

Word 尽量在原模板结构上作最小替换，保护段落样式、节属性、批注锚点和修订。LaTeX 保留标签、公式、引用和项目宏。按约定生成标记版或修改说明。

工作稿语言由读者决定，不强制将所有英文回复改成口语或半中半英。

### ④ 作者修改工作稿

只有需要作者作研究判断或作者明确要求手改时，等待对应反馈。已有授权且无未决判断的修改继续推进；本步骤不额外制造批准环节。

### ⑤ 合并作者修改，生成 clean 版

作者明确修改过的措辞优先保留。若发现数字、逻辑或引用冲突，指出具体位置并提出最小修改，不静默撤销作者修改。

移除面向内部讨论的过程备注，按交付约定处理修订色和批注；marked 与 clean 分开命名。提供本轮改动摘要。

### ⑥ 核对意见与正文是否对应

逐条核对意见、回复和正文落点，尤其核对回复中声称已添加的内容是否真实存在。不能把写了回复等同于完成正文修改。

尚未处理的事项用四项说明：意见原文、当前写法、未解决部分、建议处理。仅在用户要求时使用内联红底纹；其余情况放在 sheet 中。

核对重点是证据、回应完整性和格式保留，不以坏词零命中或自评分数代替判断。

### ⑦ 根据反馈完成本轮交付

落实追加反馈，交付正文、回复和必要的修改说明。新改动引入问题时定向修复；没有新问题时停止，不为了凑轮数反复改稿。

内部工作稿可保留明确的待办；最终提交版不得把待办或虚构数值当成完成结果。提交给会议、期刊或公开平台是独立操作，须有对应授权。

## 实施约定

- 事实、数据、引用和作者确认的研究范围不随润色改变。
- 页数、字体、引用格式和颜色按目标 venue 或项目要求确定，不沿用私人历史模板。
- 修改说明定位到节、段落或文件位置，不只写“已修改”。
- 仅语言修改不引入新实验承诺，不把 rebuttal 的防御性说明大段搬入论文正文。
- 处理 Word 时按本轮预期判断批注和修订增减，不能一概要求计数不变。
- 编译采用项目已有工具链；编译或渲染受限时说明具体未确认项，不声称已完成视觉检查。
- 只有任务需要时才使用 [round-playbook.md](round-playbook.md) 中的整轮组织方式。
