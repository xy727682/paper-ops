# 修订模板

以下均为空白模板，不包含实际审稿意见或实验结果。按任务选用，不要求每轮全部生成。

## 单表 addressing

| 意见 ID | 来源与原文 | 要求 | 回应要点 | 证据来源 | 正文位置 | 状态 |
|---|---|---|---|---|---|---|
| | | | | | | |

状态可使用：待分析、待材料、待作者判断、已修改、已核对。拆分意见时保留父意见 ID。

## Logic

```text
问题 ID：
意见原文：
对方要求说明什么：
我们的立场：
理由与证据链：
证据能支持到哪里：
缺少什么材料：
回复中的落点：
正文中的落点：
```

## Response

```text
Reviewer comment [ID]
[审稿人原文]

Response
[直接回答问题或说明立场。]
[给出相关证据及其含义。]
[说明做了什么修改、位于哪里，必要时摘录修改后的正文。]
```

是否致谢、引用是否逐条编号、是否粘贴完整修改段，按目标 venue 和回应需要确定。

## 尚未解决的事项

```text
意见原文：
当前正文或回复：
未覆盖的部分：
建议处理与所需材料：
```

## 本轮交付说明

```text
本轮底稿：
已修改范围：
正文与回复文件：
标记版与 clean 版：
已核对事项：
仍需作者判断的事项：
尚未完成的编译或渲染步骤（若有）：
```

修订配色是项目约定，不是全局标准。未建立配色时可先用 diff 或修改说明，避免与作者原有颜色冲突。
